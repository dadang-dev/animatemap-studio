# Architecture

Project v15 adds bounded immutable historical datasets and a historical layer with a scene-local year track. Actual v14 validation is retained for migration. The v15 validator checks the whole registry (10 MiB/100,000 vertices), scene workload (eight layers/100,000 referenced source vertices), identities, timing and supported tracks before atomic edits or API persistence. Source URLs are metadata; no source fetch occurs during evaluation or export. A disposable validation worker reviews pinned SHA-verified bundled manifests and local manifests before an undoable addition. Exact source snapshots remain untouched; the shared evaluator produces source/missing/blocked states or checked, explicitly illustrative single-region morph geometry. A separate map adapter unwraps render copies across the dateline, preserving holes/parts. Source year/uncertainty labels are shared DOM overlays and credits enter ordinary render, multi-pass and interchange. Graphic manifest v1 accepts actual project versions 14 and 15, retaining existing ZIP compatibility.

Graphic manifest v1 / `zip` jobs leave project v14 unchanged. Shared RenderView evaluates once per frame and MapRenderer prepares map, transparent overlay, global captions and raw GPU depth passes without editing project state. Crossfade exports unweighted outgoing/incoming planes with the exact blend weight. DepthCapture listens immediately after final public map paint, copies default GPU depth into owned targets, encodes RGB24, restores GL state and disposes resources; adding a style layer was rejected because it changes the scene's depth ranges. Opacity masks retain DOM measurement and restore in reverse order. Serial fflate STORE archives flush bounded entries before another screenshot, preserve canonical project/source/rights metadata and remove incomplete files on cancellation/failure. A final signal check occurs after cleanup, before completion is reported. See `phases/phase-6/MULTIPASS.md` for protocol limits and evidence.

Project v14 adds an immutable `modelAssets` registry (five assets, 3 MiB/20,000 triangles total) and up to 20 model instances/40,000 drawn triangles per scene. Actual v13 validation remains available; migration adds empty model assets, nullable camera follow and empty motion/altitude tracks. Local OBJ parses in an abortable 15-second worker, validates geometry including GPU precision, retains original-byte SHA/units/up axis/origin/provenance and never resolves external resources. Model poses use pure scene-local geodesic progress, shortest heading rotation, AGL altitude and editable scale/orientation. Follow references an existing same-scene model, derives centre/heading/AGL without modifying manual camera keys and updates immediately on seeking/editing. Native canvas preview now applies to models as well as terrain/buildings. `modelsAdapter` owns actual WebGL2 programs/buffers/VAOs, shared 3D depth, nearest-world-copy placement and deletion cleanup. DEM ground is required after readiness when terrain is enabled; missing elevation and lost context fail explicitly. Credits enter overlay, interchange and reports. See `phases/phase-6/MODELS_FOLLOW.md`.

Building contract introduced in v13, retained by v14. `buildingDatasets` embeds at most three declared-source footprint/AGL-height registries, totaling 3 MiB and 20,000 vertices. Each has up to 500 records, 512 vertices per footprint and budgeted topology checks. A `buildings` layer references a dataset and owns color, gradient, opacity and scene-local height-scale animation. The evaluator computes height scale; `buildingsAdapter` preserves polygons/holes/parts and converts declared units into MapLibre fill-extrusion metres. Source geometry is cached by immutable dataset; shared lifecycle/order/picking handles deletion, reorder and same-ID type changes. Disposable importer workers have a 15-second deadline. Review/apply, dataset references, history, templates, autosave and API validation use the same contract. Preview uses native canvas dimensions for terrain or building projects, visually scaled to fit. Renderer/AE/worker reports retain building credit and survey year.

React editor → versioned project → pure animation evaluator → MapLibre adapter and DOM overlays. The render worker uses the same renderer in Chromium at fixed timestamps, then FFmpeg. Fastify serves local persistence and jobs on loopback. No external tile service is enabled by default.

Workspace packages expose TypeScript sources consumed by Vite/tsx. Root TypeScript checks all packages together. Schema boundaries reject invalid data before persistence or render. UI state (selection, playback, history) is separate from project JSON.

## Ownership and interfaces

- `project-schema`: Zod project v14 contracts, typed layers, embedded PNG/PCM/provenance, building and observation registries, Admin 1 catalog references, captions, label collision settings, bounded media/geometry/coverage validation, pinned optional terrain/camera bounds, tested v1–v13 migration, restricted AI proposal contracts, job response contracts and fixture factory. Scene/keyframe times are local seconds; scene start maps them to project time. Audio/captions use project seconds. Unsupported versions fail explicitly.
- `animation-core`: `evaluateProjectAt(project, seconds)` returns scene ID, camera and evaluated layer copies, plus an optional outgoing scene state and incoming blend weight. Crossfade holds the preceding final visible frame and evaluates the incoming scene live. Easing registry, short-arc longitude/bearing and length-based geodesic trim have no React/DOM/clock dependency. Route arcs are sampled at ≤50 km intervals and longitude-unwrapped for rendering.
- `map-engine`: MapRenderer owns MapLibre, geometry sources, projected overlays, local worker URL and readiness checks. During crossfade it owns a second inert renderer for the outgoing frame; readiness and failure handling cover both, and the secondary renderer is disposed after the transition. User IDs are namespaced away from internal base-map layers. Preview scales project zoom/line widths/fonts; export scale is 1. Polygons retain islands and holes.
- `web`: Zustand project transactions validate snapshots and hold bounded undo history. Selection, draft camera, drawing points and playback are transient. Pure scene operations mutate transaction clones and reflow a contiguous sequence, maintaining transition bounds. ScenePanel owns scene controls, Timeline shows global scene bounds and scene-local keys. IndexedDB autosave and atomic local templates are separate from explicit API saves. Inspector, ProjectMenu and ExportPanel own UI concerns; MapSurface is shared by editor and RenderView.
- `api`: loopback Fastify routes wrap JsonRepository and JobQueue. Repository uses temporary-file rename for atomic writes. Worker queue clones submitted projects, serializes jobs and aborts Chromium/FFmpeg on cancellation. Cross-origin requests, hostile hosts and unsupported providers are rejected.
- `render-worker`: isolated production renderer at port 5174, fixed frame-index evaluation, readiness/retry, screenshots, shell-free FFmpeg, cleanup and reports. Editor port 5173 supports HMR independently.

## Project and API contracts

Project v6 contains canvas/FPS/duration, bundled provider/style/provenance, embedded assets, scenes with cut/crossfade transitions, camera tracks and discriminated layers. Layers carry visibility, locking, time range, opacity, transforms and opacity/reveal and overlay transform tracks. Text/marker/image anchors are WGS84 map coordinates or normalized screen coordinates. Image layers and country textures reference validated asset IDs. ImageResources evicts inactive references, bounds decoding readiness and uses local pixels; source metadata is never fetched. Shapes store line/arrow points or exactly four cubic Bezier controls; render state adds a sampled, geodesically trimmed path without mutating project controls. Longitudes unwrap before cubic sampling. Editor-only projected controls live outside MapRenderer. Validated v1 projects migrate with cuts; v1/v2 migrations add empty transform tracks; v1–v5 add an empty asset registry. Original fixtures remain v1 to exercise migration. The evaluator expects validated projects; persistence and jobs enforce that boundary.

V7 adds always-show/hide-overlap policy and priority for text/marker labels. The animation core selects labels from full-project-pixel rectangles without DOM or prior-frame state. MapRenderer supplies font measurements, projected anchors and transformed bounds, after pinned fonts load. Marker pins remain independent of hidden text. Both scene renderers apply this policy during crossfade; screenshots use the same adapter.

V8 adds a bounded dataset registry with declared provenance and a choropleth layer referencing normalized country/year/value observations. CSV/XLSX parsing runs in a disposable worker with a deadline; ZIP metadata, expanded bytes, checksums and worksheet bounds are checked before ExcelJS reads a sanitized archive. Mapping/review precedes a single validated editor transaction. The pure evaluator samples scene-local data-year keys, interpolates or holds observations without extrapolation, and computes fixed-domain colors. The renderer consumes those colors and creates a shared legend using an opaque pixel ramp to avoid CSS gradient dithering. Source credits and worker reports include active datasets. V1–v7 migrations add empty datasets/data-year tracks, preserving prior validators.

V9 adds source-stable Admin 1 references and persistent boundary visibility. Geometry remains outside project JSON in 251 verified local country files. Per-renderer resources stream with pinned length/SHA-256 and time limits, abort unused requests and evict inactive geometry. Eight-country coverage is enforced across every scene; unknown region references fail before persistence/jobs. Both crossfade renderers wait for geometry. The same source supports selection, optional outlines and animated highlights. Old versions migrate with empty boundary visibility.

V10 adds canonical PCM WAV assets, global audio clips and caption cues, with empty migrations for previous versions. AudioPlayback owns active decoded buffers/scheduled Web Audio sources, and the playback hook restarts sources for edits/seeks. The pure evaluator returns gains/source offsets and active captions; global caption composition remains independent of scene blends. FFmpeg performs real bounded PCM mixing and AAC/Opus muxing using local temporary inputs. MediaRecorder capture is explicit, reviewed and stops/releases streams on every exit. Schema/API validation enforces references, source/project bounds and media budgets. API storage is configurable with `ANIMATEMAP_STORAGE_DIR`; Playwright uses its own workspace directory.

V11 adds optional validated geographic provenance on imported markers/routes. Previous validators remain intact, and migrations preserve evaluator inputs. GeographyService owns a source-verified offline gazetteer and optional fixed-origin Openrouteservice adapter. Hosted search filters to OSM sources and rejects mixed-source results. Account keys/limits live only in server process memory; status/results never include credentials or raw provider error content. One bounded, cancellable request is active at a time. Explicit result review adds a layer in one undoable transaction; the evaluator and renderer subsequently use only stored coordinates. Source metadata references the original import and explicitly allows later geometry editing.

V12 adds disabled-by-default, catalog-pinned regional terrain; actual v11 validation/migration preserves all existing 2D media/geography. Camera keys must remain in the verified pack at usable zoom. TerrainAdapter installs/removes MapLibre DEM/hillshade, owns no animation clock and accepts only fixed local protocol paths. Each tile is length/SHA-verified before decoding, with bounded transfer/cache and abort/deadline. MapSurface uses native project dimensions with visual CSS scaling while terrain is enabled, keeping DEM detail and ground projection identical to capture/interchange. Readiness redraws projected overlays after terrain settles. Source geometry/type/order caches avoid redundant terrain texture invalidation and are cleared for replacements/deletions. Runtime terrain is offline; source provenance resides in the pinned catalog and render reports.

Routes: GET health/projects/project-by-ID; POST projects; DELETE project-by-ID. Health returns `{status:"ok",schemaVersion:14}`; project list returns `[{id,name}]`. Geography routes: GET status, POST configure/search/route/cancel, DELETE configure. Render routes and response states are documented in RENDER_PIPELINE. All project names/text use plain text DOM APIs; there is no rich HTML rendering.

## Reviewed Codex proposals

GET `/api/ai/status` discovers a local executable without reading account files. POST `/api/ai/propose` validates a prompt, current project and generation UUID, reserves one active run and invokes the installed CLI with argument arrays and a filtered environment. Authentication remains with the CLI. Its default model is used; no separate API key or implicit model override is introduced. Shell/agent/plugin/browser tools are disabled, rules/config are ignored, and the run is ephemeral/read-only in an owned empty directory. Prompt context contains only a bounded project summary, country catalog and 80 ranked verified places, excluding existing text/media contents. It is sent to the signed-in Codex service; this feature requires network access.

The proposal v1 contract accepts camera keys, source country codes, verified place IDs, illustrative paths and plain Unicode text. Normalization resolves coordinates from the pinned local gazetteer and emits an ordinary v11 project. Unknown places/countries, invented polygons, executable/remote asset fields and invalid timing reject. The structured output schema uses disjoint literal branches with `anyOf`, compatible with the installed provider, while strict Zod validation remains authoritative. CLI event types, output bytes, file size and the two-minute deadline are bounded; unsupported tool events discard the proposal. POST `/api/ai/cancel` requires the caller's generation UUID, so a closing idle dialog does not cancel another tab's run. Cleanup verifies the owned directory before removal and leaves saved projects intact.

AIPanel displays the validated JSON before any edit. Apply checks that the project still matches its captured snapshot and has no locked layers/audio/captions, then creates one undoable replacement. It preserves canvas/provider/style and replaces scenes/media. Discard, cancellation and failures leave the original project unchanged. The accepted project enters the existing evaluator/render pipeline, without model calls during playback/export.

## After Effects interchange

The independent animation-core interchange module validates versioned camera/anchor samples and emits a trusted ASCII ES3 JSX template. Existing project v11 stays unchanged. `sampleAfterEffects` owns a cloned snapshot and an offscreen MapRenderer with full canvas dimensions, evaluates `i/fps`, waits for resources and reads projected anchor samples. The same projection method draws preview overlays. Samples include evaluated offsets/scale/rotation, collision visibility and separate crossfade scene weights; no editor seek/state mutation occurs. Cancellation, close, timeout and resource errors dispose the renderer. A bounded JSON registry carries attribution and identifies scenes/layers; JSX uses escaped literals to create geographic metadata sliders and 2D attachment nulls, without arbitrary code or native 3D camera conversion. Artifact/UI tests and a labeled API contract harness are separate from the pending actual Adobe host gate.

## Limits

No external service is configured by default. Optional routing uses only the fixed official HTTPS provider, with redirects prohibited; arbitrary remote URLs are never accepted. Natural Earth is a country-scale basemap and place gazetteer, not a street-map service. Vector layers render below DOM overlays, with reorder within each plane. API job status is in memory; saved JSON projects and completed artifacts persist. Cloud hosting, authentication, distributed jobs and remaining P2 modules are tracked in the phase roadmap.
