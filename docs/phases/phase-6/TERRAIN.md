# Phase 7A.1 — Licensed offline 3D terrain

Status: terrain module acceptance passed. Codex acceptance and local After Effects artifact checks passed first; external Adobe/routing gates remain open. This is the first independently gated part of 7A. Buildings, model ingestion, camera follow and multi-pass graphics remain separate required modules.

Source: [AWS Terrain Tiles registry](https://registry.opendata.aws/terrain-tiles/) documents public S3 access without an account and points to [Tilezen/Joerd source attribution](https://github.com/tilezen/joerd/blob/master/docs/attribution.md). A bounded regional Sa Pa pack contains nine original 256×256 Terrarium PNGs at zoom 9, covering longitude 102.65625–104.765625 and latitude 21.289374–23.241346. Original bytes total 864969; per-file SHA-256, source URL, retrieval time and decoded range will be retained. This is a pinned retrieval snapshot, not a newly released survey or a navigation-grade dataset. Source values, including negative elevations, remain unchanged.

The direct source/MapLibre probe loaded only local tiles, rendered an actual pitched terrain mesh/hillshade and returned elevation 2576.519 meters at [103.8,22.3], without map errors. No synthetic elevation was generated. Source encoding follows the [Terrarium format specification](https://github.com/tilezen/joerd/blob/master/docs/formats.md). MapLibre 6.4.1 is pinned; its local source confirms `project()` includes terrain and `queryTerrainElevation()` returns exaggerated elevation. Preview and export must use identical DEM resolution/viewport to avoid lower-resolution preview tiles changing ground projection.

Files/interfaces:

- Pinned regional DEM catalog/assets, full license/source notices and reproducible checksum validation. Runtime requests only catalog paths, with bounds, byte/hash checks, timeouts and abort; no third-party terrain URL is accepted.
- Schema v12 adds nullable map terrain configuration with source pack/exaggeration/hillshade. Retain actual v11 validation and tested v1–v11 migration to disabled terrain. Camera keys must stay within the supported pack and usable zoom range for terrain projects; unknown packs reject. Existing 2D content remains unchanged.
- A separate terrain adapter owns source/layer installation and removal. Full-size deterministic terrain previews are visually scaled to fit the editor; the same renderer/resources drive PNG/MP4 and AE sampling. Ground-projected overlays remain tied to terrain. Missing/corrupt resources fail visibly before capture.
- Terrain controls review source/coverage, enable with an explicitly reviewed camera replacement, change exaggeration/hillshade, disable, undo/redo and persist. No invented building heights or model geometry enters this module.

Acceptance:

- [x] Original DEM bytes/hashes/encoding/ranges and license notices are verified.
- [x] Schema migration, provider allowlist, camera bounds, controls/history/persistence and style changes pass.
- [x] Real 3D mesh differs from flat rendering and uses verified source heights; preview overlay anchors align during pan/pitch.
- [x] Exact repeated seeks/PNG and decoded MP4 parity pass with attribution visible; cancel/resource failure preserves saved projects.
- [x] Static/unit/integration/browser/build/format/audit and relevant regressions pass.

Risks/checks: terrain's center elevation and tile readiness can make projection depend on earlier frames. Pin viewport/DEM, settle ground elevation after resources, and prove repeated-seek/export equality. Regional coverage must be visible; cameras outside the pack must not silently invent terrain. Full-resolution preview has a GPU cost that must be documented and profiled. Native 3D model placement and independent depth/beauty passes require later validated contracts rather than being represented by this terrain gate.

Implementation: `terrain.ts` supplies pinned configuration/catalog and camera bounds; actual v11 validation remains intact, and v1–v11 migrate with terrain disabled. `terrainAdapter.ts` owns a fixed protocol and verifies local tile length/SHA before worker decoding, with abort/15-second deadlines and a nine-tile verified byte cache. Transfer copies avoid detaching cached bytes. No remote provider/URL or missing-height substitute is accepted. The regional viewport uses original zoom-9 data; camera keys require zoom ≥10 and source coverage. Terrain/height exaggeration/hillshade controls support history, source review, explicit camera replacement, styles and autosave. New Codex proposals remain 2D and explicitly disable terrain. Reports and AE manifests retain enabled terrain credits/source metadata.

MapSurface renders enabled terrain at native project dimensions and scales the whole surface visually. Pointer conversion accounts for CSS scaling; ordinary 2D preview scaling is unchanged. Ready redraws ground overlays after terrain settles. Unchanged layer ordering and route geometry no longer trigger redundant style/source updates that invalidate terrain render-to-texture stacks; type changes/deleted sources invalidate the cache. Rendering still uses the ordinary evaluator and shared adapter, including FFmpeg.

Validation so far: `pnpm check` passed 129 unit/integration tests in 44 files with TypeScript/lint/build. Three terrain/foundation browser scenarios passed in four minutes, including explicit UI construction, native preview, source height, camera changes, style/history/autosave, real MP4/PNG, exact repeated seeks, ground anchors, flat comparison, active terrain-export cancellation and actual missing/corrupt resources with saved-project recovery. MP4: 1920×1080/30 FPS/H.264/yuv420p, 60 frames. Decoded frame mean absolute RGB errors at 0/30/59: 1.9698/2.0666/2.3555 (<3/255); PNG frame 30 is pixel-identical. At 1.2× exaggeration the probe is 3091.823 metres, consistent with the source-derived ground value. `terrain-parity.json`/`terrain-ffprobe.json` retain evidence; ignored `.local/reviewed/terrain/` retains reviewed PNG/flat/video output.

An initial browser run exposed an invalid min-zoom setter used while disabling terrain; removing this terrain-side mutation preserved the existing 2D initialization. A second run progressed to 49 captures but exceeded the original three-minute test deadline. Redundant style reordering/source updates were removed, and the test uses a bounded five-minute job allowance while retaining identical visual tolerances. The successful worker report measured 124.763 seconds for 60 native 1080p terrain frames plus encoding on this development machine. This is a measured cost, not a playback/render SLA. Larger terrain captures require more time/GPU memory. Broader source-cache/type-change, 2D, crossfade, data and interchange regressions remain the final gate.

Final renderer verification: `pnpm check` passed all 129 tests/typecheck/lint/build after the cache changes. Eleven existing browser scenarios passed in the broader regression (interchange/resource errors, camera seeks, crossfade MP4, CSV/XLSX, choropleth MP4/PNG, editor, map and golden frames). The new cache fixture omitted its required time range; after correcting the fixture, cache invalidation/type replacement and the real map scenario passed together in 32.3 seconds. This verifies no updates for unchanged evaluated route geometry, real updates for changed points, and source/layer recreation for same-ID type replacement. In total 15 unique relevant browser scenarios passed, with one map repeat. This terrain gate does not complete the remaining 3D building/model/follow/multi-pass modules or external host/service gates.

`pnpm format:check` passed for the final files and `pnpm audit --prod` reported no known vulnerabilities. Local checks are complete; hosted CI still awaits a remote repository.
