# Phase 7A.4 — Deterministic compositing passes

Status: completed after models/follow passed its separate gates. Project v14 remains unchanged; graphic manifest v1 and the `zip` job format are new contracts.

Files/interfaces:

- Keep project v14 unchanged. Extend the export-job format registry with a bounded ZIP sequence of actual beauty/map, transparent DOM overlays, full reference frames and GPU depth images, plus a versioned frame manifest. Each frame uses the shared evaluator at `i/fps`; source credits remain in the overlay and reference footage. Audio stays in separately available ordinary video exports.
- A dedicated WebGL2 depth-capture adapter copies the actual final rendered depth buffer into an owned texture/framebuffer and encodes it losslessly into RGB24. Values are normalized GPU window depth, including MapLibre's layer ranges, not physical ground distance or a fabricated scene depth. Unsupported framebuffer formats/context/resources fail explicitly. Depth capture must preserve beauty pixels and dispose all owned GL resources.
- Render-page pass preparation changes only visibility of shared map/overlay planes. The preview adapter and resource/font/image/terrain readiness stay identical. Crossfade requires separate outgoing/incoming map/overlay planes with their manifest blend weights; one flattened blended depth is not presented as physical geometry.
- Stream bounded PNG bytes into an owned ZIP archive; cap frame count/uncompressed bytes and honor queue cancellation/backpressure. Remove incomplete archive and temporary files on failure/cancel, preserving immutable snapshots and saved projects. API/CLI/editor use the same format metadata.

Acceptance:

- [x] Actual GPU depth varies over terrain/model geometry, repeats on seeking, rejects lost context and releases resources; building/ordinary map regressions remain passing.
- [x] Export archives contain real full-size PNGs with deterministic names/frame timestamps and validated manifest/source credit; transparent overlay and map composite match full reference with unchanged visual tolerance.
- [x] Crossfade outputs preserve separate source planes/weights; depth is explicitly normalized GPU depth per scene.
- [x] UI/API/CLI export, bounded inputs, queue cancellation/failure/retry and cleanup pass without affecting existing formats or saved content.
- [x] Unit/integration/browser/static/build/format/audit gates and affected checks pass.

Risks: hardware depth-buffer formats and terrain rendering require actual browser validation. Capturing several full-resolution PNGs per frame increases CPU/GPU/disk usage; bounded sequence limits and measured timings are required before any performance claim. DOM text/markers/images/legends/captions have no 3D depth and are provided as transparent overlays, not invented geometry.

Files/interfaces implemented: `project-schema/multipass.ts` owns versioned manifest, exact frame/path/dimension validation, limits and raw RGB24 decoder. `map-engine/depthCapture.ts` owns shader/VAO, depth/color textures and framebuffers, saved GL state and post-paint readback. MapRenderer owns pass opacity snapshots, unweighted source-plane masks, global caption plane, credits and restoration. RenderView exposes `frame(index)` then `pass(kind, plane)` with the same evaluator/resources. `render-worker/graphicArchive.ts` streams STORE ZIP entries through bounded serial file writes; `graphicFrames.ts` captures ready PNGs at the already evaluated frame. API queue, CLI and editor use the shared `zip` format. fflate remains pinned at 0.8.3 (existing MIT notice); worker declares its dependency and root uses the same pinned decoder for independent archive tests.

Archive contents: compact immutable `project.json`, validated `manifest.json`, `README.txt`; each frame has `reference.png`, transparent `captions.png`, incoming map/overlay/depth, plus separate outgoing map/overlay/depth during crossfade. Frame count is `ceil(duration × FPS)`, times are `index/FPS`. Source credits remain in overlay PNGs and manifest. Composite map + overlay per scene, outgoing group over incoming at `1-incomingWeight`, then captions last. Reference files and ordinary PNG export remain pixel-identical to native preview. Eight-bit transparent PNG/compositor rounding permits the existing 3/255 mean RGB tolerance when recombining planes. Audio is preserved in the project snapshot and available in MP4/WebM; ZIP does not mix it.

Depth PNG is raw packed data: `(R×65536 + G×256 + B)/16777215`. It is normalized GPU window depth, including MapLibre's layer ranges, and cannot be presented as linear ground distance. Decode raw bytes before any color conversion; use nearest samples and do not interpolate/gamma-correct packed RGB. Different scene cameras keep separate depth images during crossfade. Tested Chromium's depth buffer is 24-bit with 8-bit stencil; 16/24/32-bit supported formats are checked at runtime and unsupported copies fail explicitly. No height/label-depth fallback is fabricated.

Bounds: 600 frames, 8,294,400 pixels (landscape/portrait 4K), 64 MiB per entry, 1 GiB archive, 5,000 entries and ten-minute sequence deadline. PNG bytes are already compressed, so STORE avoids recompressing them. Each entry flushes before the next screenshot; incomplete archives stay in owned temporary frame folders and are removed. Fixed 1980 ZIP timestamps describe archive reproducibility, not source dates. Cancellation also checks final browser/file cleanup before reporting completion, removing an otherwise finished artifact if cancellation arrives then. Snapshots and API projects remain intact.
