# Phase 7E — Authenticated shared projects

Status: local authenticated collaboration implemented and all local module acceptance gates passed on 2026-10-14. Release v15 local regression (75 default scenarios plus one real Codex opt-in) and actual 300-frame benchmark passed before this module. Public cloud deployment remains a distinct unverified gate.

Scope: build real account/session/role-protected shared project persistence through the API, with explicit snapshot revisions and conflicts. Users create a local account through the UI; no external identity provider or API key is required for development verification. Validate collaboration using independent browser contexts and real requests, not intercepted endpoints. Keep the existing offline editor, project JSON contract and render pipeline independent of authentication. Local-only API routes remain available for the existing local mode. Deployment must not be enabled automatically.

Files/interfaces:

- A separate server collaboration service owns persisted user records, salted password hashes, hashed expiring session tokens, owner/editor/viewer membership and versioned project documents under an ignored dedicated storage root. Public response contracts exclude password/session hashes. Password processing, request sizes, account/session/document/member counts, storage paths and resource usage are bounded. Session cookies are HttpOnly/SameSite, and auth/role checks apply to every shared-project route.
- A versioned shared-document contract wraps the existing validated v15 project with a revision and membership metadata; editor project JSON itself does not change. Create/read/list/update/share/revoke/delete operations are atomic within the single server. Updates require the current revision; stale writes return 409 with the current document, preserving both saved server state and the caller's local draft. No automatic merge or forced overwrite.
- A shared-project dialog provides registration/login/logout, list/create/open/save, member roles and explicit conflict recovery: load the server revision or save the local draft as a separate project. Loading replaces local editing state only on an explicit action and retains undo where appropriate; credentials are not written to project JSON, IndexedDB or logs. Shared saves persist original geography/media and do not invoke rendering or Codex.
- Unit/integration tests exercise hashes/session expiry/authentication, role enforcement, owner protection, revision concurrency, atomic failure/persistence/restart, source preservation, quotas and hostile inputs. Browser tests use two actual account sessions and verify shared editing/conflicts, local draft preservation, roles/revocation, logout and unchanged local export.

Acceptance:

- [x] Account/session data survive service restart securely; unauthorized requests cannot enumerate or mutate shared documents.
- [x] Two real sessions share/read/edit according to roles; concurrent saves yield one accepted revision and an actionable conflict, with no silent data loss.
- [x] UI preserves local drafts on errors/conflicts and resolves conflicts through explicit server-load or independent-copy actions.
- [x] Original validated project geometry/assets/timing persist through sharing; malformed updates and service failures retain the last saved document.
- [x] Static/unit/integration/build/format/audit and affected real browser/export gates pass.
- [ ] Actual remotely hosted multi-user deployment is verified with configured TLS, secure-cookie/origin policy, storage/backups and operational limits before claiming a cloud release.

Risks: authentication introduces credential and quota handling; local loopback verification is not public-cloud security certification. A single process can serialize atomic revision updates, but multiple server processes need a transactional database/lock contract. Concurrent editing is snapshot collaboration with conflicts, not real-time CRDT co-editing. Optional deployment and billing remain visibly unconfigured until their actual environments exist; do not implement fake payment success or invented hosted URLs.

Implementation: a separate `@animatemap/project-schema/collaboration` entry point defines credentials/public accounts/shared header/member/document/update contracts, retaining project v15. AccountService stores only per-user random 16-byte salts, 64-byte scrypt hashes and SHA-256 digests of random 32-byte session tokens. Stable Node crypto uses N=131072/r=8/p=1, maxmem 256 MiB, with one serialized hash operation and a maximum eight pending operations. Sources: [Node 24 crypto documentation](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback), [OWASP password storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html#scrypt). Unknown-user login also computes the same password KDF before returning the same invalid-credentials response. Passwords allow 12–128 characters/256 UTF-8 bytes; account names are bounded ASCII and case-insensitive. Auth attempts are limited to ten/minute per client and account name, with a bounded tracking map. Accounts max 100; five sessions/account and 200 total; sessions expire after seven days and explicit logout invalidates the digest. Local cookies are HttpOnly/SameSite=Strict with an API-only path; responses use no-store. HTTPS/secure cookies are still required for any future remote deployment.

SharedProjects stores one validated wrapper per UUID with project snapshot, members and monotonically increasing revision. Owner/editor can save, viewer can read, only owner grants/revokes/deletes, and ownership cannot be removed/transferred. Missing membership is a 404; unauthorized operations are 403. All mutations are serialized in one process, require the prior revision and atomically rename a flushed temporary file. A stale save/membership/delete returns 409 plus the authorized current document; no forced overwrite. Limits: 30 shared documents, 32 MiB/document/request, 256 MiB total, 20 members/document, and eight pending operations. Stored account data is bounded to 512 KiB. Filenames are server UUIDs; source metadata is not fetched. Storage is under `collaboration/` beside the configured local project directory, ignored by Git; temp creation requests mode 0600 (Windows deployment still needs explicit ACL review).

Project → Shared projects · accounts provides real registration/login/logout, create/list/open/save, roles, revocation/deletion and conflict recovery. Selection/revision stays transient across dialog close/reopen so users can edit the main map then save against the originally loaded revision. Closing a dialog does not rewrite the local project. Browser refresh restores the session cookie, but shared binding is transient: explicitly open a server project again; local autosave remains available. Loading the server state is one undoable replacement. Saving a separate copy preserves the local draft. No password/token goes into project JSON, IndexedDB or logs; users may choose a browser password manager normally.
